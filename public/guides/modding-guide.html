Modding Guide

Everything you need to know to create custom content for Blastback Engine games — from simple entities to complex AI-driven enemies and custom weapons.

Prerequisites
Before diving in, make sure you have read the Getting Started guide and understand the basics of the Entity Scripting system and Behavior Trees.

Introduction for Modders

Blastback Engine's data-driven architecture makes it straightforward to add new content without modifying the engine itself. All game content — entities, weapons, enemies, projectiles, and UI — is defined through JSON files and sprite assets placed in the correct directories. The engine discovers and loads your content automatically based on file naming conventions.

This guide walks you through the full workflow of creating custom content, from setting up your project structure to debugging common issues.

Project File Structure

Blastback mods follow a specific directory structure within the Content folder. Keeping your files organized correctly is essential for the engine to discover them.

Directory Structure
Content/
  Sprites/
    enemies/           # Enemy sprite files (.ase, .png, .atlas)
    weapons/           # Weapon sprites
    projectiles/       # Projectile sprites
    props/             # Prop and decoration sprites
    ui/                # UI element sprites
  Entities/
    enemies/
      *.mob.json       # Mob entity definitions
    weapons/
      *.weapon.json    # Weapon entity definitions
    drops/
      *.drop.json      # Drop/pickup definitions
    projectiles/
      *.projectile.json  # Projectile definitions
    props/
      *.json           # Prop and decoration entities
  BehaviorTrees/
    bt.*.json          # Behavior tree templates
Tip
Subdirectories inside Entities/ are optional but recommended for organization. The engine scans all subdirectories recursively, so you can nest folders as deeply as you need.

File Naming Conventions

PatternModel TypeExample
[name].mob.jsonMob (enemies, NPCs)goblin.mob.json
[name].weapon.jsonWeaponlaser_rifle.weapon.json
[name].projectile.jsonProjectilefireball.projectile.json
[name].drop.jsonItem drophealth_potion.drop.json
bt.[id].jsonBehavior treebt.patrol_and_chase.json

Creating Custom Entities

Every entity starts as a JSON file. The filename determines the entity ID, and the suffix before .json determines the model type. At minimum, an entity needs a name and visualsPath.

Minimal Entity Example

decoration_lamp.json
{
  "name": "Lamp",
  "visualsPath": "props/lamp",
  "renderLayer": 8,
  "colliderSizeX": 8,
  "colliderSizeY": 16,
  "physicsLayer": 6,
  "collisionLayerMask": [1]
}

Interactive Entity with Events

Add a commandMap to make an entity react to events:

chest.json
{
  "name": "Treasure Chest",
  "visualsPath": "props/chest",
  "renderLayer": 7,
  "colliderSizeX": 16,
  "colliderSizeY": 12,
  "isTrigger": true,
  "physicsLayer": 6,
  "collisionLayerMask": [2],
  "components": {
    "trigger": {
      "commandMap": {
        "onPlayerEnter": "entity.emit openChest"
      },
      "events": {
        "onCollision": ["onPlayerEnter"]
      }
    }
  },
  "model": {
    "events": {
      "openChest": {
        "spawnDrop": { "lootTable": "common" },
        "playSound": { "id": "chest_open" }
      }
    }
  }
}

Creating Custom Weapons

Weapons are entities with a WeaponModel and weapon-specific components. The two primary weapon types are ranged (using shooterComponent) and melee (using meleeComponent).

WeaponModel
The base data model for all weapons. Defines cooldown, ammo capacity, and visual representation.
ShooterComponent
Handles projectile spawning, fire rate, spread, burst fire, and muzzle offsets for ranged weapons.
MeleeComponent
Handles melee swing arcs, hit detection zones, combo chains, and impact timing for close-range weapons.
weaponComponent
Base component shared by all weapons. Defines damage, knockback force, and weapon type classification.

Ranged Weapon Example

plasma_cannon.weapon.json
{
  "name": "Plasma Cannon",
  "visualsPath": "weapons/plasma_cannon",
  "renderLayer": 4,
  "components": {
    "weaponComponent": {
      "damage": 20,
      "knockback": 80,
      "type": "ranged"
    },
    "shooterComponent": {
      "projectileEntity": "plasma_bolt",
      "fireRate": 0.4,
      "spread": 3.0,
      "burstCount": 1,
      "muzzleOffset": 8.0
    },
    "animator": {
      "triggers": {
        "fire": { "muzzleFlash": 1 }
      }
    }
  },
  "model": {
    "cooldown": 0.4,
    "maxAmmo": 30,
    "visual": {
      "sprite": "plasma_cannon",
      "scale": 1.0
    }
  }
}

ShooterComponent Fields

FieldTypeDescription
projectileEntitystringThe entity ID of the projectile to spawn.
fireRatefloatMinimum seconds between shots.
spreadfloatRandom angle spread in degrees for each shot.
burstCountintNumber of projectiles fired per trigger pull.
burstDelayfloatDelay in seconds between burst projectiles.
muzzleOffsetfloatDistance in pixels from the entity center to spawn projectiles.

Melee Weapon Example

battle_axe.weapon.json
{
  "name": "Battle Axe",
  "visualsPath": "weapons/battle_axe",
  "renderLayer": 4,
  "components": {
    "weaponComponent": {
      "damage": 35,
      "knockback": 150,
      "type": "melee"
    },
    "meleeComponent": {
      "swingArc": 120,
      "hitRadius": 20,
      "comboCount": 2
    },
    "animator": {
      "triggers": {
        "swing": { "impact": 4 }
      }
    }
  },
  "model": {
    "cooldown": 0.8,
    "maxAmmo": -1,
    "visual": {
      "sprite": "battle_axe",
      "scale": 1.2
    }
  }
}

MeleeComponent Fields

FieldTypeDescription
swingArcfloatThe angular width of the melee swing in degrees.
hitRadiusfloatThe reach of the melee attack in pixels.
comboCountintNumber of swings in a combo chain before cooldown.
Note
Melee weapons should set maxAmmo to -1 in the model to indicate unlimited use. Melee attacks use physics layer 8 (Melee Impacts) for hit detection.

Creating the Projectile Entity

Ranged weapons require a corresponding projectile entity referenced by the projectileEntity field:

plasma_bolt.projectile.json
{
  "name": "Plasma Bolt",
  "visualsPath": "projectiles/plasma_bolt",
  "renderLayer": 3,
  "colliderSizeX": 6,
  "colliderSizeY": 6,
  "isTrigger": true,
  "physicsLayer": 4,
  "collisionLayerMask": [1, 3],
  "model": {
    "speed": 200.0,
    "damage": 20,
    "lifetime": 3.0,
    "piercing": false,
    "gravity": 0.0
  }
}

Creating Custom Enemies

A custom enemy requires at minimum three components: an AI component for behavior, a mob component for health and damage, and a movement component for locomotion.

AI Component
References a behavior tree template via templateID and provides resolution overrides for entity-specific behavior.
MobComponent
Defines health, contact damage, invincibility frames, and knockback properties for damageable entities.
Movement Component
Controls movement speed. Used by AI commands like ai.moveToTarget and ai.patrol.
Animator Component
Maps animation triggers to frame events, enabling synchronized attacks, sounds, and visual effects.

Complete Enemy Example

fire_imp.mob.json
{
  "name": "Fire Imp",
  "visualsPath": "enemies/fire_imp",
  "renderLayer": 5,
  "colliderSizeX": 10,
  "colliderSizeY": 14,
  "physicsLayer": 3,
  "collisionLayerMask": [1, 2, 4, 5],
  "components": {
    "animator": {
      "triggers": {
        "attack": { "cast": 5, "release": 8 }
      }
    },
    "ai": {
      "templateID": "ranged_chase",
      "resolution": {
        "attackAction": {
          "commands": ["entity.animate attack,once"]
        }
      }
    },
    "mob": {
      "health": 25,
      "damage": 8,
      "invincibilityTime": 0.2,
      "knockbackForce": 100
    },
    "movement": {
      "speed": 55.0
    },
    "weaponHandler": {}
  },
  "model": {
    "id": "fire_imp",
    "namespc": "enemies",
    "animation": {},
    "events": {
      "animator.attack.release": {
        "fireProjectile": {}
      }
    }
  }
}

MobComponent Fields

FieldTypeDescription
healthintMaximum hit points for the entity.
damageintContact damage dealt to the player on collision.
invincibilityTimefloatSeconds of invulnerability after taking a hit.
knockbackForcefloatForce applied to the entity when hit.
Tip
Use the resolution field in the AI component to customize shared behavior tree templates for each enemy. Many enemies can share the same BT file but with different attack animations, patrol distances, and reactions. See the Resolution System documentation for details.

Custom UI Elements

The engine provides a set of UI components for building in-game interfaces. UI elements are defined similarly to other entities but target the UI rendering layer.

Bar / BarGroup
Health bars, energy bars, stamina bars, and grouped bar displays with customizable colors and segments.
Button
Interactive buttons with hover states, click commands, and configurable visual styles.
Text / Image
Static and dynamic text labels, formatted strings, and image display elements.
SelectionGroup
Menu navigation, inventory grids, and selection interfaces with keyboard and gamepad support.
Panel / Container
Layout containers for grouping and positioning child UI elements with alignment and padding options.
Tooltip / Dialog
Context-sensitive tooltips and dialog boxes for item descriptions, NPC conversations, and system alerts.
Example: Custom health bar UI
{
  "name": "PlayerHealthBar",
  "visualsPath": "ui/health_bar",
  "renderLayer": 0,
  "components": {
    "uiBar": {
      "trackedValue": "player.health",
      "maxValue": "player.maxHealth",
      "fillColor": "#e74c3c",
      "backgroundColor": "#2c3e50",
      "width": 120,
      "height": 12
    },
    "uiPosition": {
      "anchor": "topLeft",
      "offsetX": 16,
      "offsetY": 16
    }
  }
}
Example: Interactive menu button
{
  "name": "StartButton",
  "visualsPath": "ui/button_large",
  "renderLayer": 0,
  "components": {
    "uiButton": {
      "label": "Start Game",
      "fontSize": 16,
      "commandMap": {
        "onClick": "game.loadScene main_level",
        "onHover": "entity.animate hover,loop"
      }
    },
    "uiPosition": {
      "anchor": "center",
      "offsetX": 0,
      "offsetY": 40
    }
  }
}

Tips and Best Practices

  • Use shared BT templates — Define common behavior patterns in bt.*.json files and customize via the resolution system rather than duplicating trees.
  • Keep physics layers minimal — Only include necessary layers in collisionLayerMask to improve performance and avoid unintended interactions.
  • Use renderLayer wisely — Lower numbers render on top. Group similar entity types on the same layer for consistent visual ordering.
  • Name entities clearly — The name field appears in debug tools and error logs. Use descriptive, unique names.
  • Test incrementally — Start with a minimal entity definition and add components one at a time, testing after each addition.
  • Keep sprites organized — Mirror the entity folder structure in your Sprites/ directory so visualsPath references stay intuitive.
  • Use animation triggers — Synchronize gameplay events (damage, projectile spawning, sound effects) with specific animation frames via the animator component's trigger system.
  • Set maxAmmo to -1 for melee — Melee weapons should use -1 for unlimited ammo rather than a high arbitrary number.
  • Copy and modify existing entities — Start from a working entity that is similar to what you want, then change properties. This avoids missing required fields.
  • Use the AI editor — The Online AI Editor is faster and less error-prone than hand-editing behavior tree JSON.

Common Pitfalls and Debugging

Common Mistakes to Avoid
  • Missing physics layer: Entities without a physicsLayer field will not participate in collision detection at all. Always set this field for any entity that needs to collide.
  • Wrong file suffix: The model type is determined by the filename suffix. goblin.mob.json creates a mob model; goblin.json creates a generic entity without mob features like health tracking.
  • Circular BT references: Behavior tree templates that reference themselves (directly or indirectly) will cause an infinite loop at load time, crashing the engine.
  • Animation frame mismatch: Trigger frame numbers in the animator component must match actual frame indices in the .ase sprite file. Frame numbers are zero-indexed.
  • Missing visualsPath: If the sprite file does not exist at the path specified in visualsPath, the entity will load but be invisible. Check the engine console for missing asset warnings.
  • Forgotten weaponHandler: Enemies that use ranged attacks need a weaponHandler component (even if empty {}) to fire projectiles. Without it, the fireProjectile event will have no effect.
  • Collision layer 9: Layer 9 is reserved for internal engine use. Assigning entities to this layer will cause undefined behavior.
  • Bidirectional collision: Collision detection requires both entities to include each other's layer in their respective collisionLayerMask. If only one side includes the other, no collision will be detected.

Debugging Tips

Debug Tools
  • Enable the physics debug overlay to visualize colliders and trigger zones in real time.
  • Use the entity inspector to view component states, current AI node, and event logs for any entity.
  • Check the engine console for warnings about missing assets, invalid JSON syntax, and unresolved BT template references.
  • The Online AI Editor can import and validate your behavior tree files, highlighting structural errors before you test in-game.
