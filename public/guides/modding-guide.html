Modding Guide

Everything you need to know to create custom content for Blastback Engine games — from simple entities to complex AI-driven enemies.

Prerequisites
Before diving in, make sure you've read the Getting Started guide and understand the basics of the Entity Scripting system.

Project File Structure

Blastback mods follow a specific directory structure within the Content folder:

Directory Structure
Content/
  Sprites/
    enemies/         # Enemy sprite files (.ase, .png, .atlas)
    weapons/         # Weapon sprites
    projectiles/     # Projectile sprites
    ui/              # UI element sprites
  Entities/
    *.mob.json       # Mob entity definitions
    *.weapon.json    # Weapon entity definitions
    *.drop.json      # Drop/pickup definitions
    *.projectile.json  # Projectile definitions
  AI/
    bt.*.json        # Behavior tree templates

Creating Custom Entities

Every entity starts as a JSON file. The filename determines the entity ID, and the suffix before .json determines the model type.

File Naming Convention

PatternModel TypeExample
[name].mob.jsonMob (enemies, NPCs)goblin.mob.json
[name].weapon.jsonWeaponlaser_rifle.weapon.json
[name].projectile.jsonProjectilefireball.projectile.json
[name].drop.jsonItem drophealth_potion.drop.json

Minimal Entity Example

decoration_lamp.json
{
  "name": "Lamp",
  "visualsPath": "props/lamp",
  "renderLayer": 8,
  "colliderSizeX": 8,
  "colliderSizeY": 16,
  "physicsLayer": 6,
  "collisionLayerMask": [1]
}

Creating Custom Enemies

A custom enemy requires at minimum: a mob component for health/damage, a movement component, and an AI component for behavior.

fire_imp.mob.json
{
  "name": "Fire Imp",
  "visualsPath": "enemies/fire_imp",
  "renderLayer": 5,
  "colliderSizeX": 10,
  "colliderSizeY": 14,
  "physicsLayer": 3,
  "collisionLayerMask": [1, 2, 4, 5],
  "components": {
    "animator": {
      "triggers": {
        "attack": { "cast": 5, "release": 8 }
      }
    },
    "ai": {
      "templateID": "ranged_chase",
      "resolution": {
        "attackNode": {
          "commands": ["entity.animate attack,once"]
        }
      }
    },
    "mob": {
      "health": 25,
      "damage": 8,
      "invincibilityTime": 0.2,
      "knockbackForce": 100
    },
    "movement": {
      "speed": 55.0
    },
    "weaponHandler": {}
  },
  "model": {
    "id": "fire_imp",
    "namespc": "enemies",
    "animation": {},
    "events": {
      "animator.attack.release": {
        "fireProjectile": {}
      }
    }
  }
}
Tip
Use the resolution field in the AI component to customize shared behavior tree templates for each entity. This way, many enemies can share the same BT file but with different attack behaviors.

Creating Custom Weapons

Weapons are entities with a WeaponModel and weapon-specific components like ShooterComponent or MeleeComponent.

Ranged Weapon

plasma_cannon.weapon.json
{
  "name": "Plasma Cannon",
  "visualsPath": "weapons/plasma_cannon",
  "renderLayer": 4,
  "components": {
    "weaponComponent": {
      "damage": 20,
      "knockback": 80,
      "type": "ranged"
    },
    "shooterComponent": {
      "projectileEntity": "plasma_bolt",
      "fireRate": 0.4,
      "spread": 3.0,
      "burstCount": 1,
      "muzzleOffset": 8.0
    },
    "animator": {
      "triggers": {
        "fire": { "muzzleFlash": 1 }
      }
    }
  },
  "model": {
    "cooldown": 0.4,
    "maxAmmo": 30,
    "visual": {
      "sprite": "plasma_cannon",
      "scale": 1.0
    }
  }
}

Melee Weapon

battle_axe.weapon.json
{
  "name": "Battle Axe",
  "visualsPath": "weapons/battle_axe",
  "renderLayer": 4,
  "components": {
    "weaponComponent": {
      "damage": 35,
      "knockback": 150,
      "type": "melee"
    },
    "meleeComponent": {},
    "animator": {
      "triggers": {
        "swing": { "impact": 4 }
      }
    }
  },
  "model": {
    "cooldown": 0.8,
    "maxAmmo": -1,
    "visual": {
      "sprite": "battle_axe",
      "scale": 1.2
    }
  }
}

Creating Projectiles

plasma_bolt.projectile.json
{
  "name": "Plasma Bolt",
  "visualsPath": "projectiles/plasma_bolt",
  "renderLayer": 3,
  "colliderSizeX": 6,
  "colliderSizeY": 6,
  "isTrigger": true,
  "physicsLayer": 4,
  "collisionLayerMask": [1, 3],
  "model": {
    "speed": 200.0,
    "damage": 20,
    "lifetime": 3.0,
    "piercing": false,
    "gravity": 0.0
  }
}

Creating UI Elements

The engine provides 12 UI components for building interfaces:

Bar / BarGroup
Health bars, energy bars, and grouped bar displays.
Button
Interactive buttons with click commands.
Text / Image
Static text and image display elements.
SelectionGroup
Menu navigation and selection interfaces.

Tips & Best Practices

  • Use shared BT templates — Define common behavior patterns in bt.*.json files and customize via the resolution system.
  • Keep physics layers minimal — Only include necessary layers in collisionLayerMask to improve performance.
  • Use renderLayer wisely — Lower numbers render on top. Group similar entity types on the same layer.
  • Name entities clearly — The name field appears in debug tools. Use descriptive names.
  • Test incrementally — Start with a minimal entity and add components one at a time.

Common Pitfalls

Watch Out
  • Missing physics layer: Entities without physicsLayer won't collide with anything.
  • Wrong file suffix: The model type is determined by the filename suffix. goblin.mob.json creates a mob model; goblin.json would not.
  • Circular BT references: Behavior tree templates referencing themselves will cause infinite loops.
  • Animation frame mismatch: Trigger frame numbers in the animator component must match actual frames in the .ase file.
  • Missing visualsPath: If the sprite file doesn't exist at the specified path, the entity will be invisible.
