Getting Started with Blastback Engine

Welcome to the Blastback Engine documentation. This guide will walk you through the core concepts you need to understand before creating content for the engine.

What is Blastback Engine?

Blastback Engine is a 2D game engine that uses Lua scripting to define entity behavior and JSON for data definitions. It provides a rich component system, behavior tree-based AI, and a flexible event/command architecture that allows modders and developers to create complex game entities without touching engine internals.

The engine handles rendering, physics, audio, and core game loops while exposing a powerful scripting API for gameplay logic. Whether you are creating enemies, weapons, interactive props, or UI elements, the workflow revolves around JSON definitions augmented with Lua-scripted components.

Note
Blastback Engine separates data (JSON) from behavior (Lua components and behavior trees). This design makes it straightforward to create new content by assembling existing components in new configurations.

Project Structure

All game content lives inside the Content folder. Here is a typical layout:

Directory Structure
Content/
  Sprites/
    player.png
    enemies/
      slime.ase
      skeleton.atlas
  Entities/
    player.json
    enemies/
      slime.json
      skeleton.json
  BehaviorTrees/
    bt.slime_patrol.json
    bt.skeleton_chase.json

Key Directories

DirectoryPurpose
Sprites/Visual assets including sprites, spritesheets, and atlases
Entities/JSON entity definition files
BehaviorTrees/AI behavior tree JSON files
Tip
The exact folder structure can vary by project, but the Content folder is always the root for all game assets, entity definitions, and behavior tree files.

How Entities Work

Entities are the fundamental building blocks of all game objects in Blastback Engine. Every character, enemy, projectile, prop, and UI element is an entity. They are defined using JSON files with a consistent structure:

JSON
{
  "name": "MyEntity",
  "visualsPath": "Sprites/my_entity.png",
  "renderLayer": "Entities",
  "builtin": false,
  "components": [
    {
      "type": "SomeComponent",
      "parameters": {
        "speed": 100,
        "health": 50
      }
    }
  ],
  "model": {
    "type": "SomeModel",
    "data": {}
  }
}

Entity Properties

PropertyTypeDescription
namestringUnique identifier for the entity
visualsPathstringPath to the sprite or atlas file relative to Content
renderLayerstringThe rendering layer this entity draws on
builtinbooleanWhether this entity is a built-in engine entity
componentsarrayList of components attached to this entity
modelobjectOptional data model associated with the entity

File Naming Conventions

Blastback Engine relies on consistent file naming to discover and load content correctly.

File TypeConventionExample
Entity definitions[name].jsonslime.json, player.json
Behavior treesbt.[ID].jsonbt.slime_patrol.json
Sprite images[name].pngslime.png
Aseprite files[name].aseslime.ase
Atlas files[name].atlasslime.atlas
Important
Behavior tree files must be prefixed with bt. for the engine to recognize them. The ID after the prefix is used to reference the behavior tree from entity components.

Supported Visual Formats

The engine supports three visual asset formats:

FormatExtensionUse Case
PNG.pngStandard sprite images and spritesheets
Aseprite.aseAnimated sprites with frame data, tags, and layers
Atlas.atlasPacked texture atlases for optimized rendering

Physics Layers

Blastback Engine uses a layer-based physics system for collision detection. Each entity can be assigned to a physics layer and given a collision mask to control which layers it interacts with.

LayerIDDescription
Tilemap1Static world geometry and tile-based collisions
Player2Player character entities
Enemy3Enemy entities
Projectile4Bullets, arrows, and other projectiles
Weapon5Weapon pickup and held weapon entities
Props6Interactive and destructible props
Drop7Item drops and pickups
Melee Impacts8Melee attack hit detection zones
Particle10Visual particle effects with optional collision
Warning
Layer ID 9 is reserved for internal engine use. Do not assign entities to this layer.

Event and Command System

Blastback Engine uses an event/command system as the primary mechanism for communication between entities and components. This decoupled architecture allows components to interact without direct references to one another.

Events

Events are signals that something has happened. Components can listen for events and react accordingly. Common lifecycle events include:

EventDescription
entity.onStartFired when the entity is first created and initialized
entity.onVisibleFired when the entity becomes visible on screen
entity.onDestroyFired when the entity is about to be destroyed

Commands

Commands are instructions sent to entities to trigger behavior. You emit commands using entity.emit:

Lua
-- Emit a command to play an animation
entity.emit("entity.animate", { animation = "walk", loop = true })

-- Emit a custom command
entity.emit("enemy.attack", { target = playerEntity })

The event/command system is the backbone of all entity interactions. Components define which commands they respond to via the commandMap, and the engine routes messages automatically.
