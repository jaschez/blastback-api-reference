Behavior Trees Guide

Behavior trees (BTs) are the AI system used by Blastback Engine to drive entity decision-making. They provide a structured, modular way to define how enemies patrol, detect players, attack, retreat, and perform other autonomous behaviors.

What Are Behavior Trees?

A behavior tree is a hierarchical structure of nodes that are evaluated each frame. Starting from the root, the tree traverses its children in a defined order, executing commands and checking conditions along the way. Each node returns one of three states:

  • Success -- the node completed its task
  • Failure -- the node could not complete its task
  • Running -- the node is still in progress

This simple model enables surprisingly complex behaviors when nodes are composed together. Blastback uses behavior trees because they are:

  • Visual and debuggable -- the tree structure makes it easy to trace decisions
  • Modular -- subtrees can be reused across different entities via templates
  • Data-driven -- trees are defined in JSON, no Lua code required for standard AI patterns

BT Node Structure

Every node in a behavior tree has the following structure:

JSON
{
  "type": "sequence",
  "commands": [
    {
      "name": "ai.checkDistance",
      "parameters": {
        "target": "player",
        "maxDistance": 120
      }
    }
  ],
  "children": {
    "moveToTarget": {
      "type": "action",
      "commands": [
        {
          "name": "ai.moveTo",
          "parameters": {
            "target": "player",
            "speed": 60
          }
        }
      ]
    }
  }
}

Node Properties

PropertyTypeDescription
typestringThe node type (sequence, selector, action, decorator, etc.)
commandsarrayCommands to execute when this node is evaluated
childrenobjectChild nodes, keyed by their ID
parametersobjectOptional parameters specific to the node type

Core Node Types

TypeBehavior
sequenceRuns children in order. Fails if any child fails. Succeeds when all children succeed.
selectorRuns children in order. Succeeds if any child succeeds. Fails when all children fail.
actionA leaf node that executes one or more commands.
decoratorWraps a single child and modifies its result (invert, repeat, etc.).
parallelRuns all children simultaneously.

Creating BT Files

Behavior tree files must follow the naming convention bt.[ID].json and be placed in the Content/BehaviorTrees/ directory. The ID is what you reference from the AI component on an entity.

JSON
// File: bt.slime_patrol.json
{
  "root": {
    "type": "selector",
    "children": {
      "chase": {
        "type": "sequence",
        "commands": [
          {
            "name": "ai.checkDistance",
            "parameters": {
              "target": "player",
              "maxDistance": 80
            }
          }
        ],
        "children": {
          "pursue": {
            "type": "action",
            "commands": [
              {
                "name": "ai.moveTo",
                "parameters": { "target": "player" }
              }
            ]
          }
        }
      },
      "patrol": {
        "type": "action",
        "commands": [
          {
            "name": "ai.patrol",
            "parameters": {
              "radius": 40,
              "waitTime": 2.0
            }
          }
        ]
      }
    }
  }
}
Tip
The AI component references the behavior tree by its ID (the part after bt.). For a file named bt.slime_patrol.json, set the component parameter to "behaviorTree": "slime_patrol".

Node Type Identification System

In the children object, each key represents the node's ID. The node type can be identified by examining the type property within the child object. The key format "type.name" can also be used as a shorthand to identify nodes:

JSON
"children": {
  "type.name": {
    "type": "sequence",
    "commands": [...]
  }
}

This identification system allows the engine and AI editor to display and manipulate nodes by both their functional type and their semantic name within the tree.

Inline Templates vs Referenced Templates

Behavior trees support two template approaches for reusing subtrees across multiple entities:

Inline Templates

Define the full subtree directly inside the behavior tree file. This is the simplest approach and works well for behaviors unique to a single entity type.

Referenced Templates (templateID)

Reference a shared subtree by its template ID. This keeps your BT files DRY and makes it easy to update shared behaviors in one place.

JSON
{
  "chase": {
    "templateID": "common_chase",
    "parameters": {
      "speed": 80,
      "detectionRange": 100
    }
  }
}

When the engine encounters a templateID, it looks up the referenced template and injects it into the tree with the provided parameter overrides. This is particularly useful for common patterns like chasing, fleeing, or patrolling.

Resolution System

The resolution system allows behavior trees to be built modularly. When a BT file is loaded, the engine resolves all template references, merges parameters, and produces a flattened tree structure. This means:

  • Templates can reference other templates (nested resolution)
  • Parameters cascade from parent to child, with child values taking priority
  • The final resolved tree is cached for performance
Note
Resolution happens at load time, not at runtime. Once a behavior tree is loaded and resolved, it runs with zero overhead from the template system.

Commands in Nodes

Each node can have an array of commands that are executed when the node is evaluated. Commands in BT nodes serve dual purposes:

  1. Condition checking -- commands can return success or failure to control tree flow
  2. Action execution -- commands can trigger entity behavior
JSON
"commands": [
  {
    "name": "ai.checkDistance",
    "parameters": {
      "target": "player",
      "maxDistance": 100
    }
  },
  {
    "name": "ai.faceTarget",
    "parameters": {
      "target": "player"
    }
  }
]

Commands are evaluated in order. If a command returns failure, the node itself fails (for sequence-type behavior). This allows you to use commands as both guards and actions within the same node.

Common BT Commands

CommandTypeDescription
ai.checkDistanceConditionChecks if target is within a specified distance
ai.checkHealthConditionChecks if entity health is above/below a threshold
ai.moveToActionMoves entity toward a target
ai.patrolActionMoves entity between random points in a radius
ai.faceTargetActionRotates entity to face the target
ai.attackActionTriggers the entity's weapon or attack command
ai.waitActionPauses the node for a specified duration
ai.fleeActionMoves entity away from the target

Online AI Editor

Blastback Engine provides a visual browser-based tool for designing and testing behavior trees without manually editing JSON files.

Open AI Editor

The AI editor allows you to:

  • Visually construct behavior trees with drag-and-drop nodes
  • Configure node commands and parameters through a form interface
  • Export trees as properly formatted bt.[ID].json files
  • Import existing trees for editing
  • Test and validate tree structure before using it in-game
Tip
The AI editor is the recommended way to create and edit behavior trees, especially for complex multi-branch trees. Use manual JSON editing only for quick tweaks or automated pipelines.

Behavior Tree Events

Behavior tree nodes fire events that your components can listen to. These events follow the pattern ai.{nodeID}.onStart and ai.{nodeID}.onEnd:

EventDescription
ai.{nodeID}.onStartFired when a specific BT node begins execution
ai.{nodeID}.onEndFired when a specific BT node finishes (success or failure)
Lua
-- Listen for when the "chase" node starts
entity.on("ai.chase.onStart", function()
  entity.emit("entity.animate", { animation = "run" })
end)

-- Listen for when the "chase" node ends
entity.on("ai.chase.onEnd", function()
  entity.emit("entity.animate", { animation = "idle" })
end)

These events are useful for triggering animations, sound effects, or other visual feedback that should sync with AI state transitions.

Complete Example: Patrol-and-Chase Behavior Tree

Here is a full behavior tree file for an enemy that patrols an area, chases the player when they get close, attacks when in range, and retreats when health is low:

JSON
{
  "root": {
    "type": "selector",
    "children": {
      "retreat": {
        "type": "sequence",
        "commands": [
          {
            "name": "ai.checkHealth",
            "parameters": {
              "below": 0.2
            }
          }
        ],
        "children": {
          "flee": {
            "type": "action",
            "commands": [
              {
                "name": "ai.flee",
                "parameters": {
                  "target": "player",
                  "speed": 90,
                  "distance": 150
                }
              }
            ]
          }
        }
      },
      "combat": {
        "type": "sequence",
        "commands": [
          {
            "name": "ai.checkDistance",
            "parameters": {
              "target": "player",
              "maxDistance": 120
            }
          }
        ],
        "children": {
          "engage": {
            "type": "selector",
            "children": {
              "attack": {
                "type": "sequence",
                "commands": [
                  {
                    "name": "ai.checkDistance",
                    "parameters": {
                      "target": "player",
                      "maxDistance": 28
                    }
                  },
                  {
                    "name": "ai.faceTarget",
                    "parameters": { "target": "player" }
                  },
                  {
                    "name": "ai.attack",
                    "parameters": {}
                  },
                  {
                    "name": "ai.wait",
                    "parameters": { "duration": 0.8 }
                  }
                ]
              },
              "chase": {
                "type": "action",
                "commands": [
                  {
                    "name": "ai.moveTo",
                    "parameters": {
                      "target": "player",
                      "speed": 70
                    }
                  }
                ]
              }
            }
          }
        }
      },
      "idle": {
        "type": "action",
        "commands": [
          {
            "name": "ai.patrol",
            "parameters": {
              "radius": 50,
              "waitTime": 2.5,
              "speed": 30
            }
          }
        ]
      }
    }
  }
}

This behavior tree works as follows:

  1. Retreat check (highest priority) -- if health drops below 20%, the entity flees from the player.
  2. Combat -- if the player is within 120 pixels, the entity enters combat mode. Within combat, it first checks if the player is close enough to attack (28 pixels). If so, it faces the target, attacks, and waits for a cooldown. If not in attack range, it chases the player.
  3. Idle patrol (lowest priority) -- if no other condition is met, the entity patrols randomly within a 50-pixel radius.

Because the root is a selector, the tree evaluates these branches from top to bottom and executes the first one that succeeds. This creates a natural priority system where retreat overrides combat, and combat overrides patrol.
