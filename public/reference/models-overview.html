Models Overview

Models define the core data and behavior configuration for entities. Every entity has a model, and the model type is determined by the JSON file name suffix. For example, a file named shotgun_weapon.json uses a WeaponModel.

Entity Model Base Schema

All models share the following base structure:

JSON
{
  "id": "unique_model_id",
  "namespc": "game.enemies",
  "animation": {
    ...
  },
  "events": {
    "eventGroup": {
      "eventName": { ... }
    }
  }
}

Base Fields

NameTypeDescription
idstringA unique identifier for this model. Used internally for lookups and references between entities.
namespcstringThe namespace this model belongs to. Namespaces help organize models into logical groups (e.g., "game.enemies", "game.weapons").
animationAnimationDefinitionDefines the animation states, transitions, and frame data for this entity. The structure depends on the visual asset type referenced in visualsPath.
eventsDictionary<string, Dictionary<string, EventDefinition>>A nested dictionary of event groups and their event definitions. The outer key is the event group name, and the inner dictionary maps event names to their definitions.

The events field uses a two-level dictionary structure. The first level groups related events together, while the second level defines individual events within each group. This allows for organized, context-specific event handling.

JSON — Events Example
{
  "events": {
    "combat": {
      "onHit": {
        "command": "flash white",
        "sound": "sfx/hit_01"
      },
      "onDeath": {
        "command": "spawn explosion_vfx",
        "sound": "sfx/death_01"
      }
    },
    "movement": {
      "onStep": {
        "sound": "sfx/footstep_01"
      }
    }
  }
}

Model Types

The following model types are available in the Blastback Engine. Each extends the base schema with additional fields specific to its purpose.

VisualModel

VisualModel is the default model type for standard entities. It defines visual appearance, animations, and basic entity behavior. Used for mobs, NPCs, props, and any entity that needs a visual representation.

If your entity JSON file does not have a recognized name suffix, it will default to using a VisualModel.

WeaponModel

WeaponModel extends the base model with weapon-specific data such as damage values, fire rates, ammo capacity, and weapon behavior configuration.

ParticleSpawnModel

ParticleSpawnModel defines particle effect spawning behavior including emission rates, particle lifetimes, and visual properties. Used for visual effects like explosions, smoke, and environmental particles.

DropModel

DropModel configures item drop behavior including drop tables, spawn animations, and pickup interactions. Used for loot, collectibles, and any entity that can be picked up by the player.

PersistentWeaponModel

PersistentWeaponModel is a specialized weapon model for weapons that persist in the world (e.g., placed turrets, traps). Extends WeaponModel with persistence and world-placement data.

ProjectileModel

ProjectileModel defines projectile behavior including speed, trajectory, impact effects, and damage delivery.

Model Categories Summary

ModelPrimary Use
VisualModelMobs, NPCs, props, general entities
WeaponModelGuns, melee weapons, throwables
ParticleSpawnModelVisual effects, explosions, smoke
DropModelLoot, collectibles, pickups
PersistentWeaponModelTurrets, traps, placed weapons
ProjectileModelBullets, rockets, thrown objects

The model type is determined by the JSON file name suffix. Make sure your entity files are named correctly, or the engine will assign the wrong model type and your entity may not behave as expected.
