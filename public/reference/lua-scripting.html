Lua Scripting API

Complete reference for writing Lua scripts in the Blastback Engine. Scripts interact with entities through the ctx context object and engine globals.

Lua MoonSharp
Runtime
Blastback uses MoonSharp (a .NET Lua interpreter) in soft sandbox mode. Each script runs in its own isolated environment — no state leaks between scripts.

Overview

Lua scripts in Blastback are components that attach to entities via JSON definitions. Scripts can:

  • React to input and execute entity commands
  • Manage timed behaviors with timers and input buffers
  • Store and expose stateful properties to other components
  • Integrate with the entity command resolution system

Defining Lua Components in JSON

Lua components are defined in entity JSON files using the lua: prefix. All JSON properties become available in the script via ctx.config.

Entity JSON
{
  "components": {
    "lua:combat_momentum": {
      "maxTier": 5,
      "speedPerTier": 8,
      "comboTimeout": 1.5,
      "decayInterval": 0.4
    }
  }
}
Naming
The component name lua:script_id maps to a Lua script file loaded with the matching ID. Script files are located in Content/Definition/Data/Game/scripts/.

Script Lifecycle Functions

Scripts define these functions to hook into the component lifecycle:

init(ctx, config)Lifecycle

Called once when the component is added to the entity. Use this to initialize state, timers, and buffers.

ParameterTypeDescription
ctxLuaBridgeContextThe context object for interacting with the entity.
configTableLua table containing all JSON configuration values.
onAddedToEntity(ctx)Lifecycle

Called after init, when the component is fully added to the entity. Optional hook for setup that needs the context fully initialized.

update(ctx, dt)Lifecycle

Called every frame. Only invoked if the function is defined in the script.

ParameterTypeDescription
ctxLuaBridgeContextThe context object.
dtfloatDelta time for the current frame.
commands()Lifecycle

Returns a table of command handler functions. Each function is registered as an entity command and should return bool (true = success).

Lua
function commands()
  return {
    onHit = function()
      tier = tier + 1
      return true
    end,
    onBreak = function()
      tier = 0
      return true
    end
  }
end
properties()Lifecycle

Returns a table of property getter functions. Each function returns a float and is registered as a PropertyReference emitter. Values are polled when ctx.notify() is called.

Lua
function properties()
  return {
    getTier = function() return tier end,
    getBonus = function() return tier * speedPerTier end
  }
end

The ctx Object

The ctx parameter (LuaBridgeContext) is the primary interface between Lua scripts and the engine.

Command Execution

Commands are resolved through the entity's command system. All return bool indicating success/failure. Commands are cached by path after first resolution for performance.

MethodParametersDescription
ctx.command(path)stringExecute a parameterless command.
ctx.commandS(path, param)string, stringCommand with a string parameter.
ctx.commandF(path, param)string, floatCommand with a float parameter.
ctx.commandFF(path, p1, p2)string, float, floatCommand with two float parameters.
ctx.commandV(path, x, y)string, float, floatCommand with a Vector2 (passed as separate x, y).
ctx.commandB(path, param)string, boolCommand with a boolean parameter.
Vector2 Note
Vector2 values are passed as separate x and y floats due to MoonSharp interop limitations. The engine converts them internally.

Queries

ctx.queryFloat(path)Query

Query a float value from a command path. Always returns a float (converted from Lua number).

Lua
local angle = ctx.queryFloat("aimAssist.getCorrectedAngle")
local interval = ctx.queryFloat("state.refillInterval")

Events & Notifications

ctx.emit(eventID)Event

Emit an entity event. All components listening for this event ID will be notified.

Lua
ctx.emit("onDamaged")
ctx.emit("alert")
ctx.notify()Event

Notify the system that Lua-side property values have changed, triggering PropertyReference emitters to re-poll values.

Configuration

ctx.configProperty

Lua table containing all JSON configuration values from the component definition. Access values as ctx.config.key or through the config parameter in init().

Input

Access player input via ctx.input:

Property / MethodTypeDescription
ctx.input.aimXfloatX component of the aim direction.
ctx.input.aimYfloatY component of the aim direction.
ctx.input.moveXfloatX component of movement direction.
ctx.input.moveYfloatY component of movement direction.
ctx.input.flipStateboolCurrent flip/facing state of the entity.
ctx.input.check(key)boolCheck if an action key is currently pressed.

The engine Global Namespace

Global engine utilities available in all scripts.

Timers

engine.timer(interval, options?)Factory

Create a timer that expires after the given interval in seconds.

ParameterTypeDescription
intervalfloatTime in seconds until expiration.
optionstable (optional){ repeating = true } to auto-reset on expiry.

Timer methods:

MethodReturnsDescription
expired()boolTrue if timer has expired. If repeating, resets automatically.
reset()voidReset the timer to expire after the interval again.

Input Buffers

engine.buffer()Factory

Create an input buffer for storing and consuming buffered actions.

Buffer methods:

MethodReturnsDescription
set()voidMark the buffer as active.
clear()voidClear the buffered state.
isSet()boolCheck if the buffer is currently set.
consume(condition)boolIf buffered AND condition() returns true, clears buffer and returns true.

Time

FunctionReturnsDescription
engine.deltaTime()floatDelta time for the current frame.
engine.totalTime()floatTotal elapsed time since engine startup.

Integration with State Machines & Action Resolvers

State Machine Commands

Lua functions can be referenced in state machine definitions using the lua: prefix:

JSON
{
  "states": {
    "idle": {
      "onEnter": ["lua:my_script.onEnterIdle"],
      "update": ["lua:my_script.idleUpdate"],
      "transitions": [
        { "check": "action", "commands": ["lua:my_script.checkTransition"] }
      ]
    }
  },
  "globalUpdate": ["lua:my_script.update"]
}

Action Resolvers

In control handler definitions, Lua functions can resolve input actions:

JSON
{
  "controlHandler": {
    "actionMap": {
      "aim": { "resolver": "lua:action_resolvers.aim" },
      "move": { "resolver": "lua:action_resolvers.move" },
      "toss": { "resolver": "lua:action_resolvers.toss" }
    }
  }
}

Complete Examples

Action Resolver Script

code.action_resolvers.lua
function aim(ctx)
    ctx.commandV("weapon.aim", ctx.input.aimX, ctx.input.aimY)
end

function move(ctx)
    ctx.commandV("movement.move", ctx.input.moveX, ctx.input.moveY)
end

function flip(ctx)
    ctx.commandB("visual.flip", ctx.input.flipState)
end

Stateful Component with Timers

comp.combat_momentum.lua
local tier = 0
local maxTier = 5
local speedPerTier = 8
local comboWindow = nil
local decayTimer = nil

function init(_ctx, config)
    maxTier = config.maxTier or 5
    speedPerTier = config.speedPerTier or 8
    comboWindow = engine.timer(config.comboTimeout or 1.5)
    decayTimer = engine.timer(config.decayInterval or 0.4, { repeating = true })
end

function update(ctx)
    if comboWindow.expired() and tier > 0 then
        if decayTimer.expired() then
            tier = tier - 1
            ctx.notify()
        end
    end
end

function commands()
    return {
        onHit = function()
            tier = math.min(tier + 1, maxTier)
            comboWindow.reset()
            return true
        end
    }
end

function properties()
    return {
        getTier = function() return tier end,
        getSpeedBonus = function() return tier * speedPerTier end
    }
end

Buffered Input Pattern

Buffered attack example
local attackBuffer = nil

function init()
    attackBuffer = engine.buffer()
end

function update(ctx)
    if ctx.input.check("attack") then
        attackBuffer.set()
    end

    if attackBuffer.consume(function()
        return ctx.command("weapon.canAttack")
    end) then
        ctx.command("weapon.fire")
        ctx.emit("onAttack")
    end
end

Timer-based Refill

code.player_refill.lua
local refillTimer = nil

function update(ctx)
    if refillTimer == nil then
        local interval = ctx.queryFloat("state.refillInterval")
        refillTimer = engine.timer(interval, { repeating = true })
    end

    if refillTimer.expired() then
        ctx.command("reloadAmmo")
    end
end
