Components Overview

Components are modular pieces of behavior that can be attached to entities. They follow a composition-over-inheritance pattern — rather than creating specialized entity types, you compose an entity's behavior by attaching the appropriate components.

Each component is defined as a value within the entity's components dictionary. The key serves as the component's identifier on that entity.

Component Base Schema

All components share the following base structure:

JSON
{
  "commandMap": {
    "eventName": "commandToExecute",
    "anotherEvent": "anotherCommand"
  }
}

Base Fields

NameTypeDescription
commandMapDictionary<string, string>A mapping of event names to command strings. When the component receives an event matching a key, it executes the corresponding command. This is the primary mechanism for wiring up reactive behavior between components.

The commandMap allows you to connect entity events (such as entity.onStart) to component commands without writing code. Each component type defines its own set of available commands in addition to the base schema.

Component Categories

Components are organized into the following categories based on their functionality.

Common

General-purpose components used across many entity types.

ComponentDescription
animatorControls sprite animations and animation state machines.
animatorTriggerTriggers animation changes in response to events.
inputHandles input binding and action mapping.
spawnerSpawns other entities at defined positions or intervals.
triggerDefines trigger zones and their associated actions.

Mob

Components specific to mobile entities such as players, enemies, and NPCs.

ComponentDescription
aiAttaches a behavior tree to the entity for AI-driven decision making. See AI / Behavior Trees.
ControlHandlerManages control schemes and input delegation for the entity.
InteractionHandlerHandles interaction prompts and interaction logic with other entities.
MobComponentCore mob data including health, stats, and state tracking.
LevitationApplies levitation (floating) behavior to the entity.
MovementBase movement component for standard entity locomotion.
PlayerMovementPlayer-specific movement with input handling and special movement abilities.
SteeringMovementSteering-based movement for AI entities using steering behaviors.
WeaponHandlerManages weapon equipping, switching, and usage for the entity.

Weapon

Components that define weapon behaviors and mechanics.

ComponentDescription
MeleeDefines melee weapon attack behavior, hit detection, and damage.
RideableShooterShooter component for mounted or rideable weapon platforms.
ShooterRanged weapon shooting behavior including fire rate, spread, and projectile spawning.
WeaponComponentCore weapon data including damage, ammo, and weapon-type metadata.

UI

Components for building user interface elements and HUD displays.

ComponentDescription
SelectionGroupGroups selectable UI elements and manages selection state.
BarGroupContainer for multiple bar elements (e.g., health and armor bars).
BarA progress or stat bar element (health bar, loading bar, etc.).
ButtonInteractive button element with press and hover states.
ComicDisplays comic-style panels and sequential art.
ImageDisplays a static or dynamic image in the UI.
InputTriggerTriggers UI actions based on specific input events.
TextRenders text content with styling options.
UIEntityBase component that marks an entity as a UI element with layout properties.
UpgradeGroupGroups upgrade options for selection screens.
WanderAdds a subtle wandering motion to UI elements.
WaverApplies a wave-like oscillation effect to UI elements.

Most entities will use a combination of components from different categories. For example, an enemy entity might use ai, MobComponent, Movement, and WeaponHandler from the Mob category along with animator from Common.
