Entity Reference

Entities are the fundamental building blocks in the Blastback Engine. Every object in the game world — characters, projectiles, props, UI elements — is defined as an entity through a JSON file.

Entity Schema

An entity is defined by a JSON file with the following structure:

JSON
{
  "name": "my_entity",
  "visualsPath": "Characters/player",
  "renderLayer": 10,
  "builtin": [
    "Interaction.TriggerListener"
  ],
  "components": {
    "myComponent": { ... }
  },
  "model": { ... }
}

Fields

NameTypeDescription
namestringIn-game entity name, primarily used for debugging purposes.
visualsPathstringRelative path within Content/Sprites to the entity's visual asset. Supports .png, .ase, and .atlas file formats.
renderLayerintRender priority for the entity. A smaller value means higher priority (rendered on top).
builtinstring[]Array of built-in component identifiers loaded via assembly from the Blastback.Source.Gameplay namespace. For example, "Interaction.TriggerListener".
componentsDictionary<string, Entity Component>A dictionary of custom components attached to this entity. Each key is the component identifier, and the value is the component definition object. See Components Overview.
modelEntity ModelThe data model for this entity. The model type is determined by the JSON file name suffix. See Models Overview for all model types.

The builtin array lets you attach pre-compiled C# components from the engine assembly without needing to define them in JSON. For example, "Interaction.TriggerListener" resolves to Blastback.Source.Gameplay.Interaction.TriggerListener.

Functions

FunctionInputDescription
entity.emiteventID (string)Emits an event with the given ID. Other components and systems listening for this event will be notified.
Example
entity.emit "onPlayerHit"

Events

EventDescription
entity.onStartFired when the entity is added to the game world.
entity.onVisibleFired when the entity is set to visible.
entity.onDestroyFired when the entity is destroyed and removed from the world.

Events can be used in conjunction with entity.emit and the component system to create reactive behaviors without writing code.

Entity Physics Extension

Entities that participate in the physics simulation include additional fields for collision detection and response.

JSON
{
  "colliderSizeX": 16,
  "colliderSizeY": 16,
  "isTrigger": false,
  "physicsLayer": 2,
  "collisionLayerMask": [1, 3, 6]
}

Physics Fields

NameTypeDescription
colliderSizeXintWidth of the entity's collider in pixels.
colliderSizeYintHeight of the entity's collider in pixels.
isTriggerboolWhen true, the collider acts as a trigger zone — it detects overlaps but does not produce physical collision responses.
physicsLayerintThe physics layer this entity belongs to. See the layer definitions table below.
collisionLayerMaskint[]An array of physics layer IDs that this entity can collide with.

Physics Layer Definitions

Layer IDName
1Tilemap
2Player
3Enemy
4Projectile
5Weapon
6Props
7Drop
8Melee Impacts
10Particle

Use collisionLayerMask to fine-tune which objects interact. For example, a projectile on layer 4 might only collide with layers [1, 3, 6] (Tilemap, Enemy, Props) to avoid hitting the player or other projectiles.
